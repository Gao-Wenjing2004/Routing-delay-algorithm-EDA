# V9 P9：精确图证明、全距离周期转移与 Block Portal

## 结论

本轮先验证精确图，再做压缩；没有把未经证明的分支直接并入提交版。

1. 重建图上的无界 Dijkstra 在官方 1M Golden 的分层留样上达到 `4,962 / 4,962` 完全一致，误差、MAE 均为 0。
2. 横向 `0..119`、纵向 `0..549` 的 160 状态精确转移已经全部生成。原始稠密表为 `68,505,600 B`，无损稀疏化后为 `18,108,294 B`。
3. 两次分别使用 64、96 格搜索余量重建，二进制 SHA-256 完全相同：
   `E0762721427726531E8BC0DDAD84E3FF99E3CCD5E038BA64299FB62AAB6B68F2`。
4. 固定在 64 格处切断路径并不正确，抽样精确率只有 `32.22%`；保留边界两侧 `±12` Portal 带后，`24,576 / 24,576` 个可达比较全部精确。
5. Block Portal 的路径表示已被验证：在 442 条必须绕周期 Block 的长距离 Teacher 请求上，把真实 Dijkstra 骨架交给压缩转移定价器，可 `442 / 442` 精确复现。
6. 当前 Portal 候选枚举仍太慢，不能替换正式 P8。正式可提交版本仍是 P8；P9 当前是已通过正确性验证的研究分支。

## 1. Dijkstra 图正确性验证

### 1.1 验证方法

从官方 1M 请求及 Golden 中按以下维度做固定随机种子的蓄水池分层抽样：

- 距离：`0-8`、`9-16`、`17-32`、`33-64`、`65-128`、`129+`；
- 几何障碍代理：clear、Gap、Block、Block+Gap；
- Golden 延时：低延时和普通延时。

共得到 37 个实际存在的分层、4,962 条请求。每条请求都在原始 `9,632,000` 路由状态图上运行无展开上限 Dijkstra，不使用 V8 估算，也不使用有界搜索回退。

结果：

| 指标 | 结果 |
|---|---:|
| 请求数 | 4,962 |
| Dijkstra 完成数 | 4,962 |
| 与 Golden 完全相同 | 4,962 |
| 完全一致率 | 100% |
| 竞赛 Accuracy | 100% |
| MAE | 0 |

所有距离和障碍分层分别都是 100%。在“随机样本相互独立”的统计近似下，0 次失败对应的 95% 失配率上界约为 `3 / 4962 = 0.0605%`。

这不是对全部端口组合的形式化数学证明，但已经同时验证了：

- Input → Arc → Output → Net 的边定义；
- 端口起点和终点的接入规则；
- Gap 叠加；
- 可横穿 Block 的跳格和额外延时；
- 不可穿越 Block 的断路语义；
- 短、中、长距离。

因此，后续 Teacher 数据可把该无界 Dijkstra 当作可信 Golden 生成器。

## 2. 为什么不能直接收缩“连续跑道”

结构审计发现，当前图已经把 `Input → Arc → Output → Net` 收缩成了宏边，但 160 个持久路由状态中，没有状态同时满足全局入度 1、出度 1。

这意味着不能把看似连续的跑道直接合成一条边：中间状态仍可能转向或选择不同长度的 Net。安全的下一层收缩必须是“给定起止状态和位移的最短转移”，而不是删除中间节点。

## 3. 覆盖全距离的精确周期转移

### 3.1 边界 Portal 必须覆盖最大 Net 跨度

用 128 格精确轴向转移做组合消融：

| 组合方式 | 精确率 |
|---|---:|
| 强制在第 64 格落点 | 32.22% |
| 允许落点在 `64 ± 12` | 100%（24,576 / 24,576） |

固定切点失败的原因是官方 Net 最大跨度为 12，最短路径可以直接跨过第 64 格而不在该格形成状态。`±12` 不是拍脑袋阈值，而是由最大 Net 跨度推出的 Portal 边界宽度。

### 3.2 无损稀疏化

从距离 32 开始，每个“轴、方向、源状态”的可达目标状态集合保持不变：

- 120 个方向兼容源状态各有 40 个可达目标状态；
- 40 个方向不兼容源状态没有可达目标；
- 目标集合在后续距离上不再变化，只需保存延时值。

最终格式 `AXS9`：

- `<32` 的短距离保留稠密表；
- `>=32` 只保存稳定的 4,800 个可达状态对；
- 横向完整覆盖 119 格；
- 纵向完整覆盖 549 格。

| 项目 | 大小 |
|---|---:|
| 全距离稠密表 | 68,505,600 B |
| AXS9 无损稀疏表 | 18,108,294 B |
| 压缩后比例 | 26.43% |

C++ 研究定价器已可直接读取 `AXS9`，短距离走稠密地址，长距离走 40 项稀疏目标表。

若把它嵌入当前 `43,826,696 B` 的 P8 Linux 二进制，静态体积粗估为 `61,934,990 B`，低于 100 MB 限制；因此目前的主要障碍不是体积，而是在线组合次数。

## 4. Block Portal 验证

### 4.1 长距离 Teacher

使用无界 Dijkstra 新生成 160,000 条、距离至少 65 的 Teacher 请求：

| 指标 | 数值 |
|---|---:|
| 请求 | 160,000 |
| 可达 | 156,695 |
| 不可达 | 3,305 |
| clear | 789 |
| Gap only | 142,600 |
| Block only | 104 |
| Block + Gap | 13,202 |

长距离路径几乎都会遇到 Gap；因此只学习距离回归而不逐段处理 Gap，不可能接近 99%。

### 4.2 Portal 宽度来自真实最短路径

其中有 442 条请求的起终点都位于 `x=76..89`，且竖向区间穿过至少一个不可竖穿的周期 Block。真实 Dijkstra 路径经过 Block 时使用的竖向走廊为：

- 左侧：`x=70..75`；
- 右侧：`x=90..95`。

442 条全部位于理论 `±12` Portal 带内，但只有 224 条始终只使用最近的 `x=75/90`。这解释了“只设两个 Portal”为什么覆盖不足。

### 4.3 正确性与消融

| 方法 | 可完成 | 精确 | 子集 Accuracy | 每请求耗时 |
|---|---:|---:|---:|---:|
| P8/V8 回退 | 442 | — | 87.006% | 极低 |
| 最近侧 `x=75/90` | 392 | 88 | 85.577%（失败回退后） | 46.2 μs |
| 左右各 2 列 | 398 | 114 | 88.572% | 116.7 μs |
| 左右各 3 列 | 404 | 135 | 90.483% | 165.0 μs |
| 左右各 4 列 | 409 | 154 | 91.415% | 200.9 μs |
| 左右各 6 列 | 409 | 155 | 91.470% | 269.0 μs |
| 真实 Dijkstra 骨架 + AXS9 | 442 | 442 | 100% | 29.2 μs（研究上界） |

表中的 Portal 路径均是图上的合法路径，`Predicted < Golden` 的次数为 0。左右各 4 列已经接近各 6 列的准确率，说明额外带宽的收益迅速饱和。

但是，即使该困难子集 Accuracy 提升 4.41 个百分点，其出现率在长距离 Teacher 中只有 0.282%。以约 200 μs 全枚举计算，折算到 1 亿请求会增加约 56.7 秒，明显超过当前提交版仅剩的时间余量。

## 5. 为什么不能继续扩大模板表

长距离 Teacher 给出了两个不同结论：

- 只看 H/V 转向序列，一共有 55 种；Top-32 可召回 98.97%。
- 加入各局部段位移并把每个轴最后一段设为弹性余量后，仍有 97,260 种模板；156,695 条可达路径平均每个模板仅 1.61 条，Top-32 只覆盖 15.66%。

最长路径有 27 次转向。此前“17 类骨架”适合中短距离，但不能覆盖全距离。继续增加 Teacher 能提高统计量，却不会把 97,260 种具体位移模板自动变成常数时间算法。

正确方向是把重复的转向和位移吸收到周期转移中，让在线阶段不再枚举完整模板。

## 6. 下一步：把候选枚举变成真正的 Portal 转移

下一阶段不再扩大路径模板库，按以下顺序实现：

1. **定义跨 Block 的边事件 Portal**：状态包含左右侧、相对 x、上下方向、进入路由状态和 Net 跨界相位；不能只把某一条固定 y 线当 Portal，因为跨度 12 的 Net 可以跳过该线。
2. **利用方向状态降维**：160 个路由状态按进入方向恰好分成 E/N/S/W 各 40 个；跨竖向 Block 时只保留 N 或 S 的 40 状态，而不是全 160 状态。
3. **规范化六个周期 Block**：Block 1～6 形状相同、y 周期为 100，只离线计算一个标准周期的 Portal 转移。
4. **预计算 1～5 个周期的闭包**：在线直接查“跨几个 Block”的转移，不做 8～32 个候选逐条 Beam 定价。
5. **Gap 保持前缀和**：Gap 是确定性跨界费用，不展开成 Portal 节点；按具体段一次加上。
6. **在线只做三段组合**：源端局部连接 → 一个周期 Portal 转移 → 目标端局部连接；失败才回退 P8/V8。

一个方向若规范化后保留 `12 × 40 = 480` 个跨界事件状态，单个 `480 × 480` 的 `uint16` 转移约 0.46 MB；双向、1～5 周期约 4.6 MB。加上 18.11 MB AXS9 和当前 P8 二进制，仍有足够的 100 MB 体积余量。该估算必须在“跨界相位归一化确实无损”验证后才可用于正式版。
