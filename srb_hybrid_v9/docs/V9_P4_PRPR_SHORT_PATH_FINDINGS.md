# V9 P4：短距离路径重建 P0/P1 结果

## 结论

本轮按“周期原语负责普通区域、Portal 只处理破坏周期性的障碍”的路线执行了 P0 和 P1 Oracle。

当前正式提交版本暂不改变。实验已经把瓶颈进一步定位为：

1. 给定正确路径骨架，160 个完整 Routing Input 状态的周期原语计价可以精确复现 Golden；
2. 对候选路径逐段收取 Gap 费用也是精确的；
3. 目前只能可靠预测粗粒度 H/V 转向顺序，尚不能以足够少的候选恢复每个转向段的位移分配；
4. 约 34.5% 的样本目标端口没有周期状态出口，必须增加终端局部连接器。

因此，现阶段不把实验 P1 接入提交版，避免用未完成的结构算法覆盖当前 94.613722680 的稳定基线。

## 1. P0：当前失分归因

对正式 V9 P3 在官方公开 1,000,000 条 Golden 上重新逐行统计。Block/Gap 类别使用端点闭包矩形，只是便宜门控特征，不代表真实路径确实经过障碍。

| 距离 | 行数 | 准确率 | 总失分覆盖率 |
|---|---:|---:|---:|
| 0–8 | 4,448 | 62.925219 | 3.061644% |
| 9–16 | 11,163 | 74.281737 | 5.330082% |
| 17–32 | 38,602 | 84.243796 | 11.292047% |
| 33–64 | 121,672 | 90.764167 | 20.863061% |
| 65+ | 824,115 | 96.114241 | 59.453167% |

距离不超过 64 的请求占 17.5885%，但贡献 40.5468% 的总失分，准确率为 87.582995。

端点矩形分类中，`gap_only` 贡献 59.8390% 总失分，`block_only` 只贡献 0.7001%。这证明完整 Block Portal 不是当前第一优先级；无 Block 的端口进出、转向和路径相关 Gap 才是第一突破口。

最差的单元包括：

- 0–8、端点矩形无障碍：准确率 57.254237；
- 9–16、端点矩形无障碍：准确率 68.104997；
- 17–32、Gap-only：准确率 85.354951；
- 33–64、Gap-only：准确率 90.655945。

## 2. Net 跨度 8/12 核对

官方 `SRB_Net.json` 的最大 Net 跨度是 12；当前完整图、紧凑图和周期转移都包含 `dy=±12`，没有把图搜索错误截断为 8。

代码中的 `%8` 是历史回归特征和短距离记忆表维度，不是 Net 合法性限制。P0 没有发现“搜索器只允许跨度 8”的错误。

## 3. 精确教师上限

两组独立审计结果：

- 948 条距离不超过 64 的四类分层样本中，20 万展开预算内完成 782 条，782/782 与官方 Golden 完全一致；
- 9,321 条距离不超过 16、端点矩形为 clear/Gap-only 的路径样本，完整无界 Dijkstra 为 9,321/9,321 与官方 Golden 完全一致。

第一组平均每条约 116.9 ms，说明原图逐请求精确搜索不能在线使用。未完成的 166 条是预算耗尽，不是与 Golden 不一致。

当前证据支持把 Dijkstra 当作结构教师；但 10 万条全距离上限实验仍需分片并行，不能把现有约一万条审计夸大成全图证明。

## 4. 真实路径摘要

离线路径标注器新增第一/最后 Arc、完整 Routing Input 状态序列、带位移的原语序列、H/V 转向序列，以及实际 Gap、Block、Portal 事件。

9,321 条路径的 Net 步数主要集中在 4～8，转向次数主要集中在 1～3。按实际路径而不是端点矩形统计：

| 实际路径类别 | 行数 |
|---|---:|
| 无 Gap、无 Block | 3,982 |
| Gap-only | 5,296 |
| Block-only | 2 |
| Block+Gap | 41 |

这也证明端点矩形只能用于筛选：少数“端点无 Block”请求的最短路仍会靠近或穿过 Block 事件。

## 5. 路径骨架选择实验

训练/验证按完整源端点的 FNV1a 哈希切分，验证源端点不会出现在训练侧。

| 标签粒度 | Top-1 | Top-4 | Top-8 | Top-16/128 |
|---|---:|---:|---:|---:|
| 仅 H/V 转向骨架 | 52.27% | 92.26% | 98.97% | Top-16 99.89% |
| 符号骨架（每轴最后一段为余量） | 41.18% | 54.60% | 60.17% | Top-128 78.68% |
| 完整 Net 位移序列 | 1.19% | 2.00% | 2.27% | Top-128 5.52% |

结论：Top-K 分类器适合预测 H/V 转向顺序，但不适合把完整 Net 序列当成类别。在线必须根据总位移和精确路由状态生成每个转向段，而不是记忆完整路径字符串。

## 6. 周期原语计价 Oracle

从官方 Arc+Net 构建两张轴向最短连接表，完整保留 160 个 Routing Input 状态；水平和垂直分别计算，输出位移半径 32、搜索半径 64，`uint16` 合计约 6.656 MB。

### 6.1 只猜 H、V、HV、VH

只允许四种简单骨架时，对实际无障碍路径覆盖 50.53%，候选内准确率只有 87.325286。说明“先横后纵/先纵后横”远远不够。

### 6.2 已知正确骨架

把 Dijkstra 的正确转向段交给同一原语计价器，并对每条候选路径逐段收取实际 Gap 费用：

- 实际无 Block 路径：9,278 条；
- 有周期目标连接器的候选：6,077 条；
- 其中 clear 2,571 条，Gap 3,506 条；
- 精确匹配：6,077/6,077；
- 准确率：100%，MAE：0。

这一区分了三类问题：官方图/跨度/Arc 权重在当前审计范围内正确；原语计价与路径相关 Gap 正确；剩余问题是骨架生成和缺失的目标端口局部连接。

### 6.3 路由状态 Beam

在“已经知道正确骨架”的前提下，仅保留少量中间 Routing Input 状态：

| Beam | 候选数 | 候选内准确率 | 精确率 |
|---:|---:|---:|---:|
| 4 | 4,857 | 95.209055 | 84.04% |
| 8 | 5,131 | 97.481600 | 90.37% |
| 16 | 5,571 | 99.083350 | 95.44% |
| 32 | 6,077 | 99.998804 | 99.95% |
| 160 | 6,077 | 100.000000 | 100.00% |

Beam 32 是下一版结构生成器的合理准确性基线，但还需要测 C++ 每请求耗时。

## 7. 为什么不扩大在线 A*

对全部 0–8 请求盲目运行有界 A* 的消融：

| 最大展开 | 精确完成 | 全量准确率 | 精确分支内部时间/百万条 |
|---:|---:|---:|---:|
| 16 | 153 | 94.624368 | 0.226 s |
| 64 | 498 | 94.642661 | 0.484 s |
| 256 | 1,345 | 94.673131 | 1.033 s |
| 1,024 | 2,210 | 94.700560 | 3.299 s |

准确率会上升，但按一亿条外推，时间扣分远大于准确率收益，所以这些策略全部 No-Go。当前约 10 条精确门控是刻意收紧，不是代码失效。

## 8. 下一步实现顺序

1. 为缺失的约 34.5% 目标端口建立一跳/两跳终端局部连接器，仍保留完整 Routing Input 状态；
2. 用 17 类 H/V 转向骨架作为候选上层，不分类完整 Net 序列；
3. 对每个转向骨架用轴向连接表和 Beam 生成段位移，目标先达到 Top-8 结构召回率 98%；
4. 候选形成明确线段后，逐段计算 Gap，遇 Block 才进入按需事件图；
5. 在 C++ 中记录每请求候选数、Beam 操作数和微秒成本，只有总分收益为正才接入提交版；
6. P1 通过后再做单 Block 四侧绕行，不建立全局 Portal 两两大表。
