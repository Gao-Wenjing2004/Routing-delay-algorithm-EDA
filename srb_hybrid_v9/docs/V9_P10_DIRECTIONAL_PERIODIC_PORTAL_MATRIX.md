# V9 P10：方向状态降维的周期 Portal 转移矩阵

## 结论

P10 已完成并验证周期 Block 的精确核心转移：

```text
源端局部连接
  -> 一个入口 Portal 事件状态
  -> 一次周期 Portal 闭包查询
  -> 一个出口 Portal 事件状态
  -> 目标端局部连接
```

Portal 核心已经不是估算。band=6 的双方向 1～5 周期闭包同时通过：

- 独立全图无界 Dijkstra 分层抽样 `2,048/2,048` 精确；
- 真实 Block Teacher 可分解路径 `190/190` 精确；
- 压缩前后 `36,864,000/36,864,000` 个闭包值逐项相同；
- 在线单次查表约 `15.77 ns`；
- 与当前 P8 二进制合并的静态体积粗估为 `89,983,556 B`，低于 100 MB。

但 P10 **尚未替换正式 P8 提交版**。剩余问题不是 Portal 核心，而是如何对任意查询快速、稳定地产生入口和出口两个局部连接器。尚未在公开 1M 上完成局部连接器的 Accuracy/微秒消融，因此不能把 `190/190` 的 Oracle 分解结果误报成整版准确率。

## 1. 状态如何降维

完整 Routing Input 一共有 160 个状态。跨水平 Block 边界时，只可能使用与行进方向一致的状态：

- 向上只保留 40 个北向输入状态；
- 向下只保留 40 个南向输入状态。

一个跨界事件定义为“Net 跨过周期边界后落到的第一个 Routing Input 状态”。不同 Net 跨度会落在边界后的不同相位，因此不能只保存 40 个状态：

| Net 跨度 | 状态数 | 每个状态的合法落点相位数 | 事件数 |
|---:|---:|---:|---:|
| 1 | 16 | 1 | 16 |
| 2 | 8 | 2 | 16 |
| 4 | 8 | 4 | 32 |
| 12 | 8 | 12 | 96 |
| 合计 | 40 | — | 160/每个 Portal x |

P9 已证明真实 Block 绕行的垂直走廊全部位于：

```text
左侧 x = 70..75
右侧 x = 90..95
```

因此 band=6 每个方向的矩阵维度为：

```text
12 个 Portal x × 160 个方向状态/相位 = 1,920
```

这里不能继续无损合并相位。band=1 的 320 状态审计中，加性等价组为 320 个、最大组大小为 1；向上/向下分别有 205/200 个状态是某些两周期状态对的唯一最优中间状态。强行压回 40 状态会丢最短路。

## 2. 为什么先做 band=1

band=1 只保留 `x=75/90`，维度 320。它用于验证定义和定位缺失 Portal：

- 向上、向下单周期各 `102,400` 对，全部可达；
- 同一矩阵平移 100 行后，双方向各 256 对均与全图 Dijkstra 完全一致；
- 跨 2～4 周期共 1,536 个抽样状态对中，1,508 个精确，精确率 `98.1771%`；
- `Predicted < Dijkstra` 为 0，MAE 为 `0.3301`。

28 个不一致路径全部是闭包略高。回放它们的精确路径后，中间 Portal 出现在 `x=70/71/73/74/92/93`，证明误差来自 band=1 太窄，而不是周期假设或转移代价错误。这与 P9 的 `70..75 / 90..95` 结论独立吻合，因此最终扩到 band=6。

## 3. 精确矩阵生成加速

原始无界 grouped Dijkstra 会访问全器件约 963 万个状态。band=1 两方向各 102,400 个标签曾各耗时约 2 小时。

P10 给 grouped Dijkstra 增加了只用于离线 Portal 生成的空间边界。单周期路径限制在 Block 周围局部走廊后：

- band=1 双方向全部 `204,800` 个标签与原始无界结果的文件 SHA-256 分别完全相同；
- band=1 每方向缩短到约 110～117 秒；
- 专用 C++ 生成器直接写二进制矩阵，不再生成数百万行 CSV 和路径摘要；
- band=6 双方向并行生成各 3,686,400 个精确转移，用时约 1,164～1,166 秒。

最终单周期矩阵：

| 方向 | 维度 | 条目 | 不可达 | 文件大小 | SHA-256 |
|---|---:|---:|---:|---:|---|
| 向上 | 1,920 | 3,686,400 | 0 | 7,372,820 B | `8CB81795981FDEF109B5590974F4CE7885C3CAC748A95AD5331C521225F44B61` |
| 向下 | 1,920 | 3,686,400 | 0 | 7,372,820 B | `6EF3C298F224A653AD453DBAB91251F6CA1E5029BD4BB089F36F4C475663BFE3` |

## 4. 1～5 周期闭包

用单周期矩阵做 min-plus 乘法：

```text
M[1] = 单周期精确矩阵
M[k] = M[k-1] min-plus M[1]
```

每个方向计算 4 次乘法，共执行 `28,311,552,000` 次有效组合，耗时约 29.5 秒。1～5 周期每张矩阵的 3,686,400 个状态对都可达。

器件高度 550，正常在线查询最多实际使用 4 个完整周期；P10 仍按要求生成并保存第 5 周期，以便格式完整和后续扩展。

## 5. 10-bit 无损压缩与在线查询

每个周期矩阵按下式保存：

```text
cost[source,target]
  = row_base[source]
  + column_base[target]
  + residual10[source,target]
```

band=6 的最大 residual 为：

- 向上：`642 / 630 / 619 / 619 / 619`；
- 向下：`659 / 657 / 641 / 641 / 641`。

全部小于 1024，因此 10 bit 是严格无损，不是量化。结果为：

| 数据 | 大小 |
|---|---:|
| 向上原始 5 周期 uint16 | 36,864,020 B |
| 向上 10-bit | 23,078,430 B |
| 向下原始 5 周期 uint16 | 36,864,020 B |
| 向下 10-bit | 23,078,430 B |
| 双方向压缩后合计 | **46,156,860 B** |
| 当前 P8 Linux 文件 | 43,826,696 B |
| 合并粗估 | **89,983,556 B** |
| 距 100 MB 上限余量 | **10,016,444 B** |

真实在线类 `p10_periodic_portal.hpp` 不分配内存，只持有嵌入表的只读视图。查询只做两个 uint16 基值读取、一个 10-bit 随机读取和三次加法。安全的 `memcpy` 非对齐版本在 1,000 万次随机查表上为约 `15.77 ns/次`。

### 6.1 全图无界 Dijkstra

对 band=6 的两个方向、1～4 周期分别选 4 个均匀分布源状态和 64 个均匀分布目标状态：

| 方向/周期 | 行数 | 精确 | Under | Over | MAE |
|---|---:|---:|---:|---:|---:|
| 向上 1 | 256 | 256 | 0 | 0 | 0 |
| 向上 2 | 256 | 256 | 0 | 0 | 0 |
| 向上 3 | 256 | 256 | 0 | 0 | 0 |
| 向上 4 | 256 | 256 | 0 | 0 | 0 |
| 向下 1 | 256 | 256 | 0 | 0 | 0 |
| 向下 2 | 256 | 256 | 0 | 0 | 0 |
| 向下 3 | 256 | 256 | 0 | 0 | 0 |
| 向下 4 | 256 | 256 | 0 | 0 | 0 |
| 合计 | **2,048** | **2,048** | **0** | **0** | **0** |

这些标签由没有空间边界的全图无界 Dijkstra 独立生成，不复用 Portal 闭包。

### 6.2 真实 Block Teacher 路径

442 条目标 Block Teacher 中，有 190 条包含至少两个完整周期边界事件，可以严格拆成三段：

- 1 周期：111 条；
- 2 周期：47 条；
- 3 周期：32 条。

脚本从原始精确路径逐边重算 Arc、Line Gap 和 Block delay，442 条路径定价均与 Dijkstra Delay 一致，且 190 条路径的 Portal 事件全部落在 band=6 清单内。然后用：

```text
精确源局部代价 + band=6 闭包 + 精确目标局部代价
```

重新组合，结果为 `190/190` 完全等于 Golden，Under/Over 均为 0。

## 7. 剩余问题：局部连接器

Portal 核心已经解决，但在线程序不能从 Golden 路径中读取源/目标局部代价。它必须根据查询本身生成入口和出口事件。

好消息是局部结构很集中。把连续同方向 Net 合并后，190 条 Teacher 的源端局部段只有 5 类骨架：

```text
V-H-V, H-V, V-H-V-H-V, H-V-H-V, H-V-H-V-H-V
```

目标端局部段只有 11 类折叠骨架，仍被原有 17 类 H/V 骨架集合覆盖。因此下一步不应扩大 Portal 表，而应：

1. 用现有 160 状态轴向定价器实现这 5/11 类局部连接；
2. 先做 Top-1 确定性入口/出口选择，在线只查一次 Portal；
3. 若 Top-1 准确率不足，再比较 Top-2/Top-4 的准确率收益与纳秒成本；
4. 对不足两个完整周期的 252 条 Block Teacher，继续用局部/单 Block 绕行分支；
5. 在独立 Teacher 留出和完整公开 1M 上同时通过 Accuracy、微秒和总体积门槛后，才嵌入正式提交版。
