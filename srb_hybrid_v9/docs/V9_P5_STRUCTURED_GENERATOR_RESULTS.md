# V9 P5：17 类结构化路径生成器阶段结果

## 结论

P5 已把“Dijkstra 路径规律压缩成结构化生成器”的主链路打通，但**尚未接入正式提交版**。当前正式二进制仍是 P3：公开百万条准确率 `94.613722680`、大小 `20,733,408` 字节。

本阶段得到四个明确结果：

1. 修复了目标 Output 终止连接器的构建错误，目标端口覆盖由不完整变为 `288/288`；
2. 给定 Dijkstra 的真实段位移时，`160` 状态轴向表配合 Beam 32 在 `9,275` 条候选中有 `9,272` 条完全精确，准确率 `99.999216%`；
3. 17 类 H/V 骨架、弹性局部模板、逐段 Gap 和 Beam 32 已能在隐藏真实骨架的留出小样本上工作；
4. 当前瓶颈已经收敛为“用很少的候选召回正确段位移模板”，而不是端口、Gap 计费或精确定价错误。

由于 Python 原型仍需要过多候选，尚未通过“准确度收益/微秒成本”门槛，所以本轮不进入单 Block 绕行，也不覆盖稳定基线。

## 1. 目标端局部连接器修复

旧 `prpr_arch.py` 只有在目标 Output 自己还拥有后续 Net 时，才记录到该 Output 的终止 Arc。这错误地漏掉了 `128` 个逻辑输出端口（如 `A_*`、`B_*`）。查询到达目标 Output 后本应立即结束，不应要求目标还可继续走 Net。

修复后：

- 官方 Output 端口：`288`；
- 有一跳终止连接器：`288`；
- 终止连接器总数：`5,824`；
- 新增回归测试保证所有 Output 均有终止连接器。

这完成了路线中的第 1 项。现有证据没有要求额外引入一张大型目标端口 Atlas。

## 2. 17 类 H/V 骨架

短路径教师集中实际出现的骨架恰好是 `17` 类：

- `identity`；
- 从 H 或 V 开始、严格交替、长度 1～8 的 16 类骨架。

只使用查询可观察信息（源/目标端口、端口族、方向、距离带和精确位移）训练选择器，在 `1,838` 条实际无 Block 的留出路径上：

| 候选骨架数 | 真实骨架召回率 |
|---:|---:|
| 1 | 35.9086% |
| 4 | 84.5484% |
| 8 | 99.2927% |
| 16 | 100% |

因此 Top-8 是合理上层，但 Top-1 不能使用。

## 3. Beam 32 精确定价与逐段 Gap

修复终止连接器后，把 Dijkstra 的真实 H/V 段位移交给轴向状态表重新计价：

| 状态 Beam | 候选 | 完全精确 | 候选内准确率 |
|---:|---:|---:|---:|
| 160 | 9,275 | 9,275 | 100% |
| 32 | 9,275 | 9,272 | 99.999216% |

每条候选都按绝对坐标逐段检测 Gap，重复穿越会重复收费；触碰 Block 的候选在 P5 阶段直接拒绝。由此可确认：

- Beam 32 对路由状态定价足够；
- 逐段 Gap 语义正确；
- 剩余误差主要来自候选段位移没有被提出。

## 4. 平衡 Dijkstra 教师集

原 10 万条额外教师数据只使用 `100` 个源端点，却需要覆盖公开数据中的 `113` 种源端口，因此必然存在从未见过的源端口。

`generate_extra_queries.py` 新增 `--minimum-sources-per-port`。本轮为每种公开源端口至少采两个源坐标：

- 请求：`226,000`；
- 独立源端点：`226`；
- 可达精确路径：`217,870`；
- 不可达：`8,130`；
- 分组无界 Dijkstra 总墙钟时间：`113.196 s`；
- 摊销约 `0.479 ms/输出标签`。

数据仍只在本地 `build/` 中，未提交大 CSV。代码和本文记录了可复现方法。

## 5. 弹性路径模板

直接分类完整 Net 序列泛化很差。P5 改为保存局部转向模板：对 H、V 各选绝对位移最大的段作为“可伸缩主干”，其余小段保留为端口/状态切换模式；在线根据查询总位移补齐主干，再用 Beam 32 精确定价。

在 `1,838` 条无 Block 留出路径上，真实归一化模板的保守召回为：

| 每个骨架模板数 | 真实模板召回率 |
|---:|---:|
| 8 | 81.2296% |
| 16 | 86.5615% |
| 32 | 89.8803% |
| 64 | 92.3286% |
| 128 | 94.1785% |
| 256 | 95.1578% |

这是当前最清楚的失分点：扩大候选能继续提准，但不能靠无上限堆候选。

## 6. 端到端小样本消融

训练只使用独立的 22.6 万 Dijkstra 教师路径，验证使用公开路径样本的完整源端点留出桶；真实骨架和真实段位移不提供给生成器。

| 配置 | 无 Block 验证 | 完全精确 | 准确率 | Python 原型均值 |
|---|---:|---:|---:|---:|
| 已知骨架，Top-32 模板 | 98 | 89 | 96.0167% | 93.6 ms/条 |
| 已知骨架，Top-128 模板 | 98 | 92 | 98.7225% | 241.8 ms/条 |
| Top-8 骨架 × Top-32 模板 | 98 | 89 | 98.8213% | 1.437 s/条 |
| Top-8 骨架 × Top-128 模板 | 20 | 20 | 100% | 4.037 s/条 |

Python 时间只用于相对比较，不能外推 C++。不过候选数本身已经说明 Top-8×128 不可直接在线使用。20 条的 100% 只是链路可行性证据，不是总体准确率结论。

## 7. Go/No-Go 与下一步

当前结论是 **P5 算法方向 Go，正式集成 No-Go**：

- Go：目标端连接、17 类骨架、Beam 32 定价、逐段 Gap 和弹性模板都已分别验证；
- No-Go：Top-32 的真实模板召回仍约 89.9%，Top-8×32 仍需最多 256 个结构候选，尚未测出可接受的 C++ 微秒成本；
- 因此不开始单 Block 绕行，避免把次要问题混入当前主瓶颈。

下一轮应按以下顺序：

1. 将模板候选由“各层依次填满”改为带样本支持度的统一打分，抑制单样本稀疏键；
2. 从少量高分模板产生单段局部变体，同时让主干自动吸收余量，控制全局候选 Beam 为 32；
3. 实现 C++ 表驱动定价器，记录候选数、状态转移数和每请求微秒；
4. 在全部 `1,838` 条无 Block 留出路径上完成准确率/微秒消融；
5. 只有 P5 相对 V8 的总分收益为正，才处理少量真实单 Block 路径。

正式提交版在上述门槛通过前保持不变。
