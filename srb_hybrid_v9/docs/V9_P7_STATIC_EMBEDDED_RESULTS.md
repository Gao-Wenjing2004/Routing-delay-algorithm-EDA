## 1. 在线链路

每条请求只解析一次：

```text
CSV endpoint
  -> P3 解析 source/target port、x/y、dx/dy、direction、cheb
  -> 端口 ID 位图判断是否进入 P7
     -> 未命中：直接保留 P3
     -> 命中：静态索引 source_stem × direction × band × target_stem
        -> 取出固定 5 个结构模板
        -> 源端一/两跳连接器 + H/V 状态转移 + 逐段 Gap/Block + 目标连接器
        -> 有可达结果：覆盖 P3
        -> 不可达：立即回退 P3
```

选择器不再解析端口字符串，也不再计算字符串哈希。它直接使用 P3 已经得到的 `source.port`、
`environment.direction` 和 `environment.cheb` 查询 22,320 位的静态位图。

## 2. 从六层运行表压成最终静态 Beam5

P6 的 4,280,271 字节六层候选表原本需要在启动时解析为多个哈希表，并在新粗特征键第一次出现时动态评分。
P7 在离线导出阶段完成同样的支持度评分和两阶段排序，只保留 Teacher 可能命中的粗特征组合：

- 216 个端口族；
- 203 个可被选择器触发的 `source_stem × direction × coarse_band` 组；
- 每组对 216 个目标端口族保存最终 5 个模板 ID；
- 7,586 个模板使用紧凑的轴位图和局部位移保存。

最终 `p6_structured_beams.bin` 仅 563,948 字节。在线候选生成变为两次数组索引，不需要哈希表、排序、
候选缓存或冷启动学习。

按已验证的 P3 Linux 亿条投影 `107.176 s`，仅把结构分支的实测增量线性外推：

- P7 预计新增约 `5.243272 s/亿条`；

这里的 Accuracy 是完整公开 1M 实测；亿条时间和总分仍是投影值，最终以官方机器为准。
