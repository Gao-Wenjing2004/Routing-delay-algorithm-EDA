# V9 架构、消融与后续路线

## 1. 当前结构

V9 有两套精确内核，但提交版只使用紧凑内核：

1. `srb_core_v9.hpp`：完整 9,632,000 端口状态图研究内核，支持方向下界、
   26 个 Grid/Block-portal ALT Landmark、预计算目标端口状态下界、单向 A* 和
   实验性双向搜索；用于正确性审计和离线 Golden。
2. `compact_exact.hpp`：提交内核。它保存相同的端口/Arc/Net/Block/Gap 语义，
   按需生成邻边，只存本次搜索的几百个状态，并使用预计算端口状态下界。
3. `p2_estimator.hpp`：原 V8 P2 快速估算，任何未选择或预算耗尽的请求都走这里。

精确结果的安全边界是：A* 只有在堆的最小下界已经不小于当前候选值时才算完成；
达到 `max_expanded` 时绝不返回“目前最好路径”，而是设置 `budget_exhausted` 并
回退 V8。

## 2. 基线真正慢在哪里

旧 exact solver 每条查询先对 60,200 个 cell 做一次完整反向 Dijkstra，然后才
搜索端口状态。源代码虽然有 ALT 雏形，但没有在加载或查询中启用。V9 已彻底
移除这项逐查询固定工作：完整研究内核使用可复用下界，提交内核根本不构造全图。

## 3. 消融结论：为什么不是 64

固定随机 20,000 条验证切片上，单向 ALT A* 的最大预算 4096 只能完成 590 条
（2.95%），平均每条候选约 5.47 ms。把全部短距离、Block 相交或高不确定请求
直接送入搜索，准确度会上升，但按 1 亿条外推的时间代价远大于得分收益。

双向 Dijkstra 也没有改善：31 条审计样本平均展开从约 106.8 万增至 312.0 万，
总查询时间从约 47.35 秒增至 61.05 秒。因此它保留为研究代码，不进入提交版。

进一步对公开数据中全部 15,611 条 `Chebyshev <= 16` 请求做 16/64/256/1024
展开消融。16 展开是唯一仍可能产生正“准确度收益/微秒成本”的档位；256 档的
留出选择器最佳策略是“不搜索”。当前默认选择器来自容易证明的端口结构和微型
位移模板，预算固定为 16，而不是任意指定 64。

Block 相交和当前的模型分歧不确定度在本轮留出验证上均未形成正总分策略，所以
代码保留 `--select-blocks`、`--uncertainty-min` 研究开关，但正式默认不启用。

## 4. 已验证结果

| 项目 | 结果 |
|---|---:|
| V8 公开 1M accuracy | 94.603473234 |
| V9 公开 1M accuracy | 94.604410091 |
| V9 默认选择/完成 | 10 / 10 |
| 默认精确状态展开 | 52 |
| 完整 exact 已知样本 | 31/31 与旧基准相同 |
| compact/full 16-budget 等价 | 15,611/15,611 |
| Linux 单文件体积 | 约 13.5 MB |

这说明“精确搜索 + 硬回退”机制是正确且足够轻的，但当前收益仅为约
`+0.000937` accuracy point。不能把它描述成显著提分版本。

## 5. 如何让长距离最终也不用估算

完整查询字符串缓存没有价值：公开百万条精确查询几乎全唯一。应复用路径内部
结构，顺序如下：

1. **确定性跑道收缩**：把只有一个合法后继的连续 lane 合并成宏边，保留总
   Arc/Gap/Block 延时和首尾端口。
2. **Portal overlay**：以 Block 边界、Gap 线、长线切换点为 portal，在 portal
   间离线求精确最短路；在线只搜索首段、overlay 和末段。
3. **后缀 DAG**：相同目标端口类的路径后缀只保存一次，cell ID 和增量延时用
   varint/delta 编码。
4. **分层/收缩层次**：对稳定宏边做 contraction hierarchy；查询用双向上行搜索，
   但必须保留 Gap/Block 方向性，不能按普通无向网格处理。
5. **有界目标记忆**：缓存 `(target portal, target port state)` 的已结算标签，而不是
   完整 `(From,To)`。用固定容量和确定性替换，防止 1 亿条时内存失控。

关键评价指标仍是“accuracy gain / added microseconds”，并同时记录选择率、预算
完成率和 1 亿条外推总分；只看完成的查询会产生严重幸存者偏差。

## 6. 无限额外数据的正确用法

可以无限采样合法 endpoint pair，但硬件图不是无限的，也不能创造官方不存在的
端口类型。推荐分层采样短/中/长距离、Block 四周、Gap 两侧、稀有端口类别、
方向、周期相位和当前 V8 高误差桶。

标签由完整、无界 exact solver 离线产生。先做 31 条已知 Golden 一致性，再抽取
一批独立生成请求由另一实现或路径回放复核。生成集用于训练 V8/选择器，公开 1M
继续作为最终验证，避免数据泄漏。
