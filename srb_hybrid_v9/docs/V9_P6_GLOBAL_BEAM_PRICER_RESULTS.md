## 结论先行

P6 已完成 P5 文档规定的前四项工作，并严格执行第 5 项门槛。全功能 Beam32 不合入正式提交；进一步压缩出的
**六层粗粒度候选表 + Beam5 + Teacher 选择器**已经在完整公开 1M 上得到正收益，进入“可集成候选”状态。
在生成正式 Linux 单文件并完成 QA 前，仍不开始单 Block 绕行。

原因不是准确度不够。全局 Beam32 在 1,838 条无 Block 留出路径上配合 V8 回退可达到
`95.963749%`，明显高于该短路径集合上的 V8 `67.564517%`。真正的限制仍是总分中的时间项：
Beam32 即使经过 C++ 热路径优化仍需 `220.229 us/候选请求`，全选会使预计总分下降。

Beam8 加独立 Dijkstra Teacher 选择器首先给出了正收益上限。随后把候选生成压成 4.28 MB 六层表，并将在线候选
从 8 消融到 5。完整公开 1M 的实际结果为：

- P3 Accuracy：`94.613722680`；
- P6 Beam5 + P3 回退 Accuracy：`94.740555805`；
- 选择 `7,860/1,000,000`，其中结构路径完成 `6,833`；
- 复用 P3 已解析端口/位移后的 1 亿请求时间预计 `115.34–116.34 s`；
- 预计总分 `94.823–94.831`，相对 P3 约 `+0.025～+0.033`。

Accuracy 已是完整 1M 逐条实测，不是占比外推；时间和总分仍是预计值，因为 P6 尚未嵌入正式 P3 单文件。

## 1. 带支持度的统一候选评分

`analyze_global_template_beam.py` 不再按特征层级依次填满模板名额。新流程为：

1. 从所有命中特征层和骨架全局先验收集候选；
2. 用样本支持数对条件概率向骨架先验收缩；
3. 支持数小于 2 的条件证据不参与增益，避免单样本稀疏键占据 Beam；
4. 对候选统一排序，再组成一个全局 Beam，而不是每个骨架各给一个 Beam。

骨架仍采用 P5 已验证的 Top-8 选择器，因为把骨架也改为同一套概率评分会降低留出召回。这里的“统一”针对
同一批骨架下的模板候选，不意味着强行替换已经通过消融的上层选择器。

在 217,870 条平衡 Dijkstra Teacher 上训练、1,838 条公开无 Block 路径留出验证时：

| 指标 | 结果 |
|---|---:|
| 全局候选数 | 32 |
| 平均单段变体数 | 8 |
| 真实骨架被候选覆盖 | 99.292709% |
| 真实归一化模板身份召回 | 78.237214% |
| 其中由单段变体补回 | 9.303591% |

模板身份召回是保守指标；不同模板可以产生相同最短延时，最终应以精确定价后的 Delay 为准。

## 2. 单段变体与弹性主干

每个模板分别指定 H、V 方向的一个弹性主干段。局部变体只替换一条非主干段，剩余位移由主干自动吸收，
因此变体不会破坏端点总位移。候选组成如下：

- 每个 Top-8 骨架至少保留一个高分种子；
- 从少量高分种子生成单段局部变体；
- 变体最多占 8 个名额；
- 种子和变体最终共同竞争同一个全局 Beam32。

这避免了旧版 `Top-8 × Top-32 = 256` 条路径逐一计价。

## 3. C++ 表驱动定价器

新增 `src/offline_structured_pricer.cpp`。它读取 160 状态的 H/V 位移转移表，对每条候选完成：

1. 源端一跳/两跳局部连接；
2. 每个 H/V 段的状态转移；
3. 逐段绝对坐标 Gap 计费；
4. Block 相交拒绝；
5. 目标端终止连接；
6. 状态 Beam 和边 Beam 剪枝。

审计 CSV 记录 `Candidates`、`ValidCandidates`、`Transitions` 和 `ElapsedUs`。优化后只遍历存活状态，
末段直接对目标连接器定价，不再执行一次无意义的全状态剪枝。Beam32 的输出与优化前 `1,838/1,838`
完全一致，平均时间由约 `618 us` 降到 `220.229 us`。

## 4. 1,838 条无 Block 留出消融

状态 Beam 和边 Beam 固定为 32，再改变全局候选数。不可达候选统一回退 V8：

| 候选数 | 可达 | 结构分支可达口径 Accuracy | V8 回退后 Accuracy | 相对 V8 Accuracy | 平均定价时间 |
|---:|---:|---:|---:|---:|---:|
| 8 | 1,708 | 91.2773% | 88.825881% | +21.261364 | 42.120 us |
| 12 | 1,764 | 92.6646% | 91.195088% | +23.630571 | 66.939 us |
| 16 | 1,801 | 93.9648% | 93.236031% | +25.671514 | 93.247 us |
| 24 | 1,824 | 95.2942% | 95.025909% | +27.461392 | 147.120 us |
| 32 | 1,831 | 96.0510% | 95.963749% | +28.399232 | 220.229 us |

该集合上的 V8 Accuracy 为 `67.564517%`。候选越多，准确率持续提高，但时间增长更快。按官方总分公式，
五档“对所有符合条件短路径全开”的净效用均为负；Beam8 已是其中最接近可用的一档。

## 5. 独立 Teacher 选择器

为避免用公开 Golden 同时选超参数和报成绩，选择器采用两层隔离：

1. 22.6 万额外 Dijkstra 路径按完整源端点散列切分；161,174 条训练候选模型，52,831 条训练/验证选择器；
2. 选择器特征族预先固定为 `source_stem + direction + band`，仅在 Teacher 五折中选择最小支持数和 margin；
3. Teacher 选出的唯一配置为 `minimum_count=4, margin=0`；
4. 再一次性评估 1,838 条公开留出路径。

公开留出结果：

| 指标 | 数值 |
|---|---:|
| 选择 | 970 / 1,838（52.7748%） |
| 选中请求 Accuracy 增益 | +21.005849 points |
| 选中请求平均定价 | 9.214 us |
| 每个 eligible 请求的总分效用 | +4.816397 |

按公开 1M 中 `Chebyshev <= 16` 的 15,611 条和 10K 路径样本的无 Block 比例估算，eligible 占比约
`1.448%`，最终选中率约 `0.7642%`。由此得到仅计 C++ 定价器的外推：

| 项目 | 当前正式 P3 | P6 研究预计（候选生成耗时按 0） |
|---|---:|---:|
| Accuracy | 94.613723 | 94.774245 |
| 1 亿请求时间 | 107.176 s | 114.217 s |
| Time score | 94.045778 | 93.654602 |
| 总分 | 94.797845 | 94.867586 |

这组 Beam8 数字用于证明完整生成器的潜力。为真正接近提交条件，后续又完成了粗粒度表和 Beam5，见下一节。

## 6. 可内嵌六层表、记忆策略与完整 1M

把候选特征收紧为六层：

1. `source_stem + target_stem + direction + band`；
2. `source_stem + target_stem + direction`；
3. `source_stem + direction + band`；
4. `target_stem + direction + band`；
5. `direction + band`；
6. `direction`。

精确保存全部支持计数共 7,586 个弹性模板，二进制表实测 `4,280,271` bytes。160 状态轴向表为
`6,656,000` bytes；加当前 P3 Linux 文件 `20,733,408` bytes，静态体积估算约 `31,669,679` bytes，
仍远小于 100 MB。

在线记忆不缓存完整查询，而缓存粗特征键对应的最终候选 Beam。相同端口族、方向和距离段只在第一次命中时
统一评分，后续直接引用候选数组；同时去掉了每请求复制 8 个动态模板的开销。Beam5 是 5/6/7/8 消融后第一个
同时保住正总分和 120 秒余量的档位。

完整公开 1M 逐条回放：

| 指标 | 结果 |
|---|---:|
| Teacher 选择 | 7,860（0.786%） |
| 结构候选完成 | 6,833（选中请求的 86.9338%） |
| P3 Accuracy | 94.613722680 |
| P6 Beam5 + P3 回退 Accuracy | 94.740555805 |
| Accuracy 增益 | +0.126833125 |
| 热缓存选中请求联合时间 | 10.3916 us（Beam5 的多次局部中位审计为约 8.43 us） |

独立审计程序若对所有 1M 请求再次解析字符串，会额外产生 `0.147 us/请求`，线性外推约 14.7 秒。这不是正式
集成必须支付的成本：P3 在调用选择器前已经解析出源/目标端口 ID、`dx/dy` 和距离段。正式集成必须直接复用这些
字段，禁止再次解析 endpoint 字符串。

按完整 1M 的选择率和较保守的热缓存 `10.3916 us/选中请求` 计算，结构分支为 1 亿请求增加约 `8.168 s`；
当前 P3 的 `107.176 s` 增至约 `115.344 s`。首次建立粗特征缓存是一次性成本，按已观察键及全部训练键估计小于
约 1 秒，因此保守区间为 `115.34–116.34 s`。

对应预计分数：

| 项目 | P3 | P6 Beam5 候选 |
|---|---:|---:|
| Accuracy | 94.613723 | 94.740556 |
| 1 亿请求时间 | 107.176 s | 115.34–116.34 s |
| 总分 | 94.797845 | 94.823–94.831 |

## 7. 提交要求与 Go/No-Go

当前正式 P3 仍满足已知提交要求：Linux 单文件 `20,733,408` bytes，小于 100 MB；公开 1M Accuracy
`94.613722680`；百万条中位时间约 `1.07176 s`，线性投影 1 亿约 `107.176 s`；预计总分约 `94.797845`。
它可以继续提交试测。

P6 Beam5 的**算法数值**已同时跨过体积、Accuracy 正收益、120 秒和总分正收益门槛，但**提交产物**尚未通过门槛，
因为 4.28 MB 候选表、6.66 MB 轴向表和选择器还没有生成正式静态 Linux 单文件，也没有完成完整程序五次计时、
输出哈希和平台回放。因此当前状态为：

- 算法方向：**Go**；
- Beam5 + Teacher 选择器：**Go，完整 1M Accuracy 已验证**；
- 体积：**预计 Go（约 31.67 MB），待正式二进制确认**；
- 时间：**预计 Go（115.34–116.34 s），待共享解析后的正式二进制确认**；
- 正式提交：**No-Go，继续使用 P3**；
- 单 Block 绕行：**等 P6 正式集成通过后再开始**。
