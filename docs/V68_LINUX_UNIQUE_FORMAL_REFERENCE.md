# V68 Linux 唯一请求正式参考

## 结论

V68 在 Ubuntu 22.04、4 vCPU Intel Xeon Platinum 8573C、15 GiB 内存的同一 GitHub runner 上，
完成 10M、50M、100M 三档严格唯一且打散的性能测试。三档各运行五次，所有同档输出 SHA-256
一致，`formal_timing_gate = true`，时间和总分由 `pilot` 升级为 `release-reference`。

## 唯一性与打散

三档分别使用 10,000、50,000、100,000 个互斥 source fold，每源 1,000 个不重复目标。
每源的目标通过互质仿射步长映射到 1,024 个不同外存桶，消除同源连续缓存收益。

| 50,000,000 | 1,767,632,165 | 233.185 s | 0 | 0% | 1 |

10M 第一轮先删除 `/tmp/srb_runtime_atlas_v68.bin`；其余轮次复用运行时 Atlas。最终时间只加一次
冷启动差值，符合十亿条单进程执行方式。输入扫描和输出 SHA 校验另行记录，不从候选墙钟时间中扣除。

## V67 Linux 缺陷与 V68

首次 Actions 运行 `40299305315` 证明：V67 构建完 94 个 Atlas 扩展源后报
`cannot start output`。原因是 V65 起定义 `SRB_SKIP_REPEAT_PROBE`，但 `open(output)` 位于
`#ifndef SRB_SKIP_REPEAT_PROBE` 内，导致唯一输入分支的 `output_fd == -1`。

V68 只把输出文件打开移到条件编译之外；唯一分支仍用 `O_WRONLY`，预测器、Atlas、解析、批处理和
格式化均未改变。成功运行是 GitHub Actions `40302553720`，证据提交为 `66da4ac`。
