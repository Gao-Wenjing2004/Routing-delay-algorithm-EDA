# V72：冷启动消除、公开准确率 A/B 与 P10 恢复

## 当前结论

V72 已经达到本轮的时间目标，但尚未达到准确率目标：

| 指标 | V69 | V72 |
|---|---:|---:|
| 公开 1M Accuracy | 98.3781031501% | 98.3781031501% |
| 公开 1M 改变行 | — | 0 / 1,000,000 |
| Linux 冷启动 | 21.3197 s | 14.8069 s |
| 10 亿条稳态投影 | 96.3899 s | 103.3228 s |
| 冷启动 + 稳态 | 117.7096 s | 118.1298 s |
| Linux ELF | — | 80,304,456 B |

V72 用 75,632,920 B 的半径 24 精确路由态表无损替换了运行期 Base Atlas。公开
1M 上 V69/V72 的输出逐行完全相同，说明这张表解决的是启动和表示方式，不是剩余
1.62 个 Accuracy 点。V72 不应被描述为“提准版”。

Linux 10M、50M、100M 三档唯一输入的正式投影为：

```text
cold_start = 14.8069163295 s
steady_1B  = 103.3228366583 s
total_1B   = 118.1297529878 s
```

相较最初约 67 秒的 Atlas 冷启动，主要启动问题已经消除；稳态也低于 110～120 秒
目标。继续优化必须优先换 Accuracy，不能为了很小的时间收益接受预测回归。

## 分数边界

赛题公式为：

```text
total = 0.80 * accuracy
      + 0.15 * (100 - 100 * seconds / 1800)
      + 0.05 * consistency
```

按 `118.129753 s`、Consistency=100：

| Accuracy | 总分投影 |
|---:|---:|
| 98.378103% | 97.718068 |
| 99.900000% | 98.935585 |
| 100.000000% | 99.015585 |

要在该时间下达到总分 99，Accuracy 至少约为 `99.98052%`。因此“Accuracy 接近
99.9%”仍不自动等于“总分 99”；若最终 Accuracy 只有 99.9%，还需要继续缩短时间。

## P10 历史实现已恢复

远端 `v9-hybrid` 分支仍保存完整 P9/P10 研究源码。P10 不是普通残差表，而是周期
Block 的方向状态精确闭包：

```text
源端局部连接器
  -> 入口 Portal 事件
  -> 一次 1～5 周期精确闭包查询
  -> 出口 Portal 事件
  -> 目标端局部连接器
```

历史验证证据包括：

- 上/下两个方向，每方向 1,920 个 Portal 事件；
- 1～5 周期的压缩表合计 46,156,860 B；
- 36,864,000 个闭包值压缩前后逐项一致；
- 独立全图 Dijkstra 2,048/2,048 精确；
- 可严格分解的真实 Block Teacher 190/190 精确；
- 单次核心查表约 15.77 ns。

新增 workflow `p10_portal_asset_rebuild.yml` 从 `v9-hybrid` 重建图、两个单周期矩阵、
1～5 周期 min-plus 闭包和 10-bit 无损包，并以历史原始矩阵 SHA-256 为门禁。二进制
暂存为 Actions artifact，不直接写入 Git 历史。

## 为什么不能直接把 P10 接到 V72

75.63 MB 局部表与 46.16 MB P10 核心相加已经超过 100 MB，还没有计算程序本体。
而且 P10 已经证明真正的瓶颈不是核心矩阵，而是每个请求如何得到入口/出口局部连接器：
逐个枚举 1,920×1,920 事件即使精确，也无法服务十亿条请求。

当前同步进行半径 16 精确局部表审计。它只用于测算容量，不会自动成为提交版。预期
组合方向为：

1. 缩小或删除不增加 Accuracy 的局部直查表；
2. 保留 46.16 MB P10 精确核心；
3. 把源/目标局部连接器按端口路由态、坐标周期相位、Block 侧别做无损去重；
4. 在线只读取少量 Top-K 连接器与条件出口，不做 A*、Dijkstra 或大 Beam；
5. 新分支必须在公开 1M、独立源和独立区域三套数据上同时增益为正，并报告十亿条
   时间增量。

## 下一道 Go/No-Go 门槛

P10 重建完成后，先做“局部连接器模式去重审计”，不立刻写进提交热路径。必须回答：

- 精确 Top-1/2/4/8 连接器表各需要多少字节；
- 连接器列表在周期相位和路由态上有多少唯一模式；
- P10 命中率、子集 Accuracy 和全局 Accuracy 增益；
- 每个命中请求新增多少随机读取，折算十亿条增加多少秒；
- 半径 16 局部表 + P10 + 连接器 + ELF 是否严格小于 100,000,000 B。

未通过这些门槛前，V72 仍只作为时间目标已通过、准确率未提升的研究候选；不能宣称
已经达到 99.9%～100%。
