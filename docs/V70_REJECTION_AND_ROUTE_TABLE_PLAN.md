# V70 否决与 O(1) 周期方向状态表验证

## 当前结论

正式候选仍是 V68。V70 证明了稳态速度可以进入目标区间，但没有通过准确率和容量门禁，
不得提交。

| 版本/实验 | 独立 Dijkstra Accuracy | Linux 10 亿条折算 | 冷启动 | 结论 |
|---|---:|---:|---:|---|
| V68 | 98.6853086346 | 185.559 s | 67.117 s | 当前安全基线 |
| V69，无 Extension | 98.3027576768 | 117.710 s | 21.320 s | 速度快，但准确率下降 0.382551 点 |
| V70，选择性 Extension | 98.3901329267 | 首轮 156.658 s | 49.059 s | 准确率下降且 Atlas 膨胀，否决 |

V70 的首轮 Linux 稳态折算为 `107.599 s/10 亿条`，说明输入、预测、格式化和写出热路径
已经满足 110～120 秒目标。问题集中在启动时生成 Atlas，以及大表仍不能表达完整长距离状态传播。

## V70 为什么失败

V70 依据公开集差异选择了 72 个源端口，希望只生成高收益 Extension 切片。独立的 60.8 万条
源隔离 Dijkstra Golden 表明：

- Accuracy 只有 `98.3901329267%`，比 V68 低 `0.2951757079` 点；
- MAE 为 `13.729 ps`，V68 为 `11.045238 ps`；
- 这些新源端口不等价于裁剪 V68 原有的 94 个 Extension 源切片；
- 8-bit `lo + delta` 打包产生 `197,201,633` 个异常值；
- 临时 Atlas 达到 `2,775,508,776` bytes，超过 V68 原 Atlas，容量和冷启动都更差。

因此不能再按端口热度扩大或裁剪 Endpoint Atlas。端口级选择会改变图状态覆盖，并让压缩异常表爆炸。

## 160×160 方向状态周期审计

离线对每个规范路由状态运行一次无界、无 Block Dijkstra，在 `|dx|,|dy|=73..104` 的
远端区域检查水平 10、垂直 12 的周期斜率。共检查 `12,288,000` 个
`源方向状态 × 目标方向状态 × 象限 × 相位` 记录。

| 检查 | 完全相等率 | MAE | 最大误差 |
|---|---:|---:|---:|
| 水平周期斜率稳定 | 78.908789% | 0.628781 ps | 16 ps |
| 垂直周期斜率稳定 | 86.189526% | 0.352542 ps | 18 ps |
| H/V 可分离 | 84.758057% | 0.407469 ps | 16 ps |
| 二维仿射预测 | 79.452824% | 0.560916 ps | 19 ps |

结果说明简单周期不是逐值严格相等，不能宣称“精确闭式公式”；但误差已经降到亚皮秒量级，
在比赛连续评分公式下有达到 99.9% 附近的潜力。原始
`uint16 anchor + int16 x_slope + int16 y_slope` 表为 `73,728,000` bytes，连同约 5 MB
程序仍低于 100 MB。

## 全距离门禁（已完成）

近端 104 格的低误差不能直接外推到 FPGA 的 `|dy| <= 549`。当前 Linux 审计使用矩形
Dijkstra 距离场，覆盖完整 `|dx| <= 119, |dy| <= 549`，并分别统计：

1. 横坐标 0～16、17～32、33～72、73～104、105～119；
2. 纵向跨 1、2、4、8、16、32 个周期；
3. 160×160 路由状态组合；
4. Exact、MAE、最大误差及比赛 Accuracy 抽样。

审计已完成：全距离路由层抽样 Accuracy 为 `96.3106368103%`，没有达到 99.9% 门槛；
端到端 V71 独立 Golden Accuracy 也只有 `95.7071313450%`。因此二维仿射表已拒绝，详情见
`docs/V71_ROUTE_PERIOD_TABLE_RESULTS.md`。下一步改为精确坐标条件下的单轴周期审计；若仍失败，
回到小规模 Portal 状态的 min-plus 闭包，而不是增加每请求 A* 或扩大 Endpoint Atlas。

## 预定在线结构

在线只允许固定次数整数操作：

```text
源端局部连接器
  -> 方向状态/象限/10×12 相位索引
  -> 周期 anchor + 固定斜率或小型 min-plus Portal 闭包
  -> 目标端一跳/两跳连接器
  -> 必要时叠加 Block Portal / Gap 条件修正
```

不在在线热路径运行 Dijkstra/A*，不按请求记忆答案，也不利用公开数据重复性做缓存。
