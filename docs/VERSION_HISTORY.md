# SRB 延时估计版本总说明

最后更新：2026-10-02。本文是清理旧实验目录后应长期保留的总索引；源码、关键证据和大文件指纹均可从本仓库追溯。

## 版本沿革

### V1：首次官方提交

官方报告记录总分 93.79、准确度 95.27、时间 83.84、一致性 100。五次结果校验和相同。两个现存二进制完全相同，但源码未找到，所以不能把它当作可继续维护的基线。证据见 [`../legacy_versions/v1_official/`](../legacy_versions/v1_official/)。

### V2：局部 Dijkstra Atlas

V2 预先对架构图运行最短路，把有限位移内的状态距离存成 Atlas。它说明“Dijkstra 算出的结构距离很准”，也暴露两个限制：文件约 624 MiB，且公开审计证明 Atlas 命中并不等于逐条 Golden 完全相等。V2 没有独立快照，证据与复现入口见 [`../legacy_versions/v2_reference/`](../legacy_versions/v2_reference/)。

### V3：Atlas + 长距离学习回退

V3 保留半径 56、查询范围 48 的局部 Atlas；长距离或受 Block 影响的请求走常数时间回退，新增端口对、距离、余数、细位移、方向、区域和 Block 上下文特征。公开准确度从 V2 的 94.218939 提升到 95.308549，长距离从 94.225695 提升到 95.378979。源码快照见 [`../legacy_versions/v3/`](../legacy_versions/v3/)。

### V4：经过留出验证的小残差

V4 不改 V3 主体，只在 fallback 上增加 2,784 个 float 的 `single_residual`。公开准确度提升约 0.0448，固定留出提升约 0.0437。更大的 408,512 参数端口对模型虽更准，但当时因时间风险没有选入正式路径。源码和选择证据见 [`../legacy_versions/v4/`](../legacy_versions/v4/)。

### V5：运行时重建，验证 Dijkstra 的边界

V5 只内嵌原始架构，启动后运行多源/局部 Dijkstra 来生成 Geometry、局部 Atlas和端口瞬态，不读取 Golden。它把外部数据依赖消除了，但准确度只有 92.373770，且预处理约 83 秒。结论是：Dijkstra 很适合离线生成 Teacher/结构特征，不适合在每次正式运行中重建完整大表。源码见 [`../legacy_versions/v5/`](../legacy_versions/v5/)。

### V6：周期与端口族残差

V6 把 Atlas 查询半径由 48 扩到 56，并在 V3 回退上加 Macro10、port-family 和绝对相位残差，共 205,932 个 float32（823,728 bytes）。公开准确度 95.637129，是 V3 系中最有效的“小模型 + 大 Atlas”组合。源码和证据见 [`../legacy_versions/v6/`](../legacy_versions/v6/)。

### V7：旧规则最佳，但体积越界

V7 使用 base radius 24、热点 radius 72，并把压缩 Atlas、V6 模型与长距离残差嵌入单个 Linux 程序。固定留出准确度 95.647606，公开全量拟合 95.979644，五次输出完全一致；但程序为 1,271,029,532 bytes，远超新规 100 MB。完整源码、QA 和 LFS 二进制见 [`../submission_v7_20260919/`](../submission_v7_20260919/)。

### V8 P1：PRP-R 第一阶段

P1 用少量周期路由原语代替 Atlas，程序仅 8.17 MB，速度和确定性达标；但公开准确度只有 68.817773。问题不是“路径覆盖不到”：99.9978% 请求有双原语且余数不超过 12。真正问题是原语只描述骨架距离，缺少端口进入/退出、方向切换、资源代价、Block/Gap 和 Golden 生成规则，导致 98.7952% 样本低估，平均有符号误差约 -204.789 ps。P1 只能作为结构特征层，不能直接提交。详见 [`../srb_prpr_v8/`](../srb_prpr_v8/)。

### V8 P2：离线 Teacher 蒸馏

P2 不再把 P1 的结构距离当作最终数值基线，而改用 V6 的无 Atlas 常数时间回退；PRP-R 只贡献 route/state class 等结构特征。离线侧以 radius-56 Dijkstra/Atlas 结果为 Teacher，再用固定训练侧 Golden 做第二阶段校准；运行时仅携带 8+8 棵小树和固定模板，不携带 Atlas，也不执行最短路。

当前正式候选在固定 199,696 条验证集上为 94.485992，在公开全量 C++ 回放上为 94.603474。它增加三个可泛化 Q20 模板，并消除了包装层与基线的重复端点解析；连续五次输出完全一致，百万条平均 1.015910 秒，线性投影亿条 101.591 秒；Linux 静态程序 12,966,280 bytes。公开指标已跨过 94.6/120 秒/100 MB 三条线，但固定验证仍比 94.6 低 0.1140 分，所以状态仍是“可提交试测、继续优化”。完整消融见 [`../srb_prpr_v8/analysis/p2/README.md`](../srb_prpr_v8/analysis/p2/README.md)。

## 100 MB 新规下的技术结论

建议保留 Dijkstra，但改变它的位置：

1. **离线 Teacher，而非在线求解器。** 用 Dijkstra 在架构图上生成端口/状态、方向、余数和短位移样本；正式程序只携带蒸馏后的参数。
2. **Golden 是最终校准目标。** 既有审计表明结构最短路和 Golden 并非逐条等价，所以 Teacher 负责教“结构”，公开 Golden 的固定训练侧负责教“计分口径”。
3. **只记忆可泛化模板。** 可以缓存 `端口族 × 方向 × 距离段 × 周期相位/余数 × Block/Gap 类别` 的残差，或采用低秩端口 embedding；不保存完整查询或百万答案。
4. **用固定留出决定是否加入。** 每个记忆表/Teacher 特征都必须在同一个固定 20% 留出集上单独做消融；P2 当前使用按距离、Block、Gap 分层的确定性划分，只保留提升稳定且体积/时间可接受的部分。

P2 已验证方向、余数、phase、Block/Gap、小树残差和稀疏端口族模板有效。下一步不是继续扩大 PRP 原语或树数，而是研究共享叶子/低秩端口项，并按误差桶选择性启用校准；目标是利用当前约 18 秒的时间余量，把固定验证再提高至少 0.12 分。总参数预算继续控制在约 5～20 MB，给可执行文件和安全余量留下空间。

## 清理后应保留什么

- 本文作为唯一总索引；
- `legacy_versions/` 中的源码、模型清单和关键证据；
- `analysis/error_distribution_*` 的错误分布摘要；
- V7、V8 的源码与小型 QA 报告；
- 官方架构/Golden 原始数据在工作区保留至少一份，不把它当“冗余输出”删除。

可安全删除的是可重新运行生成的百万/五百万行预测 CSV、重复 benchmark 输入、编译缓存、重复旧二进制。删除前先确认相应结论已进入本文或小型 JSON/CSV 已归档。
