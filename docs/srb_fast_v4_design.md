# SRB Fast V4 设计与验证说明

状态：最小 V4 实现设计，2026-08-27。评分契约见 `docs/v4_score_contract.md`。

## 1. 设计目标

V4 不重写 V3，不在正式路径运行 A*/Dijkstra，不引入低命中缓存。目标是在相同 Atlas、相同 V3 基础模型和相同输入上，用很小的 O(1) 增量稳定提高官方 `acc_score`，并能通过 `--mode v3` 立即回退。

正式候选数据流：

```text
CSV Query
  -> V3 无分配 Slice 解析与完整端口 ID
  -> 同端点严格特例
  -> 可配置 V3 legacy Atlas（保留行为，但不标为 Exact）
  -> 与 V3 逐位等价的融合 O(1) fallback（复用 Block 计数上下文）
  -> 7 个小型常量表的相对残差修正
  -> 非负、最近整数输出
```

## 2. V3 审计结果

### 2.1 当前组成

- 端点解析：`SRB_x_y/PORT`，端口名二分查找映射到 496 个完整端口 ID。
- 局部分支：Chebyshev 距离不超过 48、端点包围盒不与 Block 相交，并且半径 56 Atlas 存在可达项。
- fallback：11 项有方向线性基线，加 18 类离散效应表、7 个 Block 相对位置项和端点 Gap 前缀差。
- V3 模型共有 996,950 个 float 参数，约 3.803 MiB；最终参数在全部公开 Golden 上拟合。
- V3 训练目标是原始 delay 残差的平方误差式回拟，不直接对齐官方相对误差 `tanh` 得分。

### 2.2 Atlas 精确性结论

公开 100 万 Golden 上，V3 实际 Atlas 命中 90,182 条，但只有 80,318 条完全一致：

| 指标 | V3 Atlas 分支 |
|---|---:|
| 命中 | 90,182 |
| 完全一致 | 80,318（89.0621%） |
| `acc_score` | 96.226478 |
| MAE | 13.2677 ps |
| P95 绝对误差 | 133 ps |
| 最大绝对误差 | 789 ps |

提高端点边界净空没有消除误差，说明不能把问题简单归因于芯片边界。可能原因包括真实最短路径离开端点包围盒、包围盒外 Block、Atlas 的规则图近似或其他未标注上下文；当前数据不能唯一定位。

因此：

- V4 保留该分支以公平复现 V3 分数，但名称为 `legacy_atlas`。
- 未通过逐条 Golden 的 Atlas 分支不得写成 Exact。
- `--disable-atlas` 可完全关闭该分支。
- 本轮不新增基于 Atlas 的“精确”范围。

### 2.3 Net 跨度 8/12

配置 `SRB_Net.json` 的最大跨度是 12；V3 `kMaximumNetSpan` 写成 8，Atlas 半径为 `48+8=56`。

100 万条中 311 条 `fallback_other` 全部是 source seed 后的残余位移超出半径 56：其中 230 个 seed 跨度为 12，81 个为 10。`LocalAtlas::get` 有边界检查，所以当前行为是安全回退，不是错误读表。

不能只把常量从 8 改成 12：这样 `kRequiredAtlasRadius` 会变成 60，现有 Atlas 会在加载时直接被拒绝。重建半径 60 Atlas预计从 653,772,840 字节增长到 749,619,240 字节，增加 91.406 MiB，而最多只恢复 311 条公开请求（0.0311%）。本轮保持关闭。

## 4. V4 残差模型

### 4.1 输入输出

基础预测是 V3 fallback 整数 `base`。残差输出为相对修正：

```text
delay_v4 = round(max(0, base * (1 + 1.25 * sum(table_j[code_j]))))
```

7 个表索引：

1. V3 预测值的 128 ps 分箱；
2. 方向编码与 Chebyshev/32 距离分箱；
3. Source/Target 到四侧边界的最小距离分箱；
4. 水平/垂直端点 Gap 跨越计数组合；
5. Block 包围盒相交数量、方向与距离组合；
6. 完整 `from_port`；
7. 完整 `to_port`。

Block 和 Gap 在这里都是统计特征，不宣称为精确延时加法。最终参数量 2,784 个 float，即 11,136 字节（10.875 KiB）。V4 将残差所需 Block 包围盒计数融合进 V3 原有 7-Block effect 循环；诊断模式 `--mode v4-base` 在公开 100 万条上与 `--mode v3` **逐字节一致**，避免为残差再扫描一次 Block。

### 4.2 训练与选择隔离

- 特征版本：`v4-compact-residual-irls-v1`。
- 固定随机种子：20260827。
- 固定 IRLS 回拟次数：3。
- 固定 `alpha=1.25`；该值在所有固定划分中一致选择后锁定。
- 每个消融实验先只在该划分训练侧重拟 V3，再只在 fallback 训练行拟合残差；验证侧不拟合表或 alpha。
- 模型结构锁定后，正式残差仅在固定随机分层的 800,304 条训练行上拟合，199,696 条永久留出；其中实际 fallback 残差训练行 728,040 条。既有 V3 基线本身曾使用全部公开 Golden 拟合，这项继承泄漏单独披露，不能把最终 V4 全量成绩称为完全独立泛化结果。
- 清单记录架构、五个 JSON、Atlas、Golden、V3 基础预测、种子和特征版本的指纹。

## 5. 固定验证划分

固定划分保存在 `analysis/srb_fast_v4/v4_fixed_splits.npz`，定义保存在 `v4_split_manifest.json`：

1. 随机分层：按距离、Block、Gap 数分层，确定性 80/20。
2. 空间区域：任一端点位于确定性留出的 16x32 区域即进入验证。
3. 长距离：Chebyshev 大于等于公开 P90（368）。
4. Block 留出：训练无包围盒 Block，验证为 Block 包围盒相关。
5. Gap 数量分层：按 Gap 数确定性 80/20。
6. 稀有端口对：完整端口对频率不超过 28。
7. 边界留出：任一端点到芯片边界不超过 8。

### 5.1 消融结论

下表为相对同划分重拟 V3 的验证 `acc_score` 增益，单位为分：

| 候选 | 参数 | 平均增益 | 最小增益 | 最大增益 | 决策 |
|---|---:|---:|---:|---:|---|
| 全局校准 | 68 | +0.00721 | -0.00602 | +0.03275 | 关闭，不稳定 |
| 单残差表 | 2,784 | +0.05412 | +0.04384 | +0.07461 | **正式候选** |
| Block 双专家 | 3,024 | +0.05556 | +0.04592 | +0.06914 | 关闭，增益不足以证明分支价值 |
| 边界三专家 | 3,776 | +0.05466 | +0.04761 | +0.06844 | 关闭，未优于双专家 |
| 端口对残差 | 408,512 | **+0.08063** | **+0.05130** | **+0.10821** | 研究态，性能证据不稳定 |

两种残差都在 7 个验证场景中提升官方准确性分，但正式选择还计入时间项。端口对版本在融合实现上的 100K、1M、5M 测量给出互相冲突的 1 亿开销外推，最大观测为 5.6369 秒；按其最弱留出集折算，保守预计总分变化为 -0.00594，故关闭。compact 版本三种规模的最大观测开销为 2.7584 秒，最弱留出集保守预计总分仍为 +0.01209。中央估计采用最终模型的 5x5M 重复输入：V3 63.6222 秒、V4 66.2127 秒；7 个切分的预计总分增益均为正，范围 +0.01349 至 +0.03810。完整计算见 `analysis/srb_fast_v4/v4_final_selection.json`。

RMSE 不一定同步改善，这是按官方相对误差计分而不是只按 RMSE 选型的预期结果。

## 7. 内存与计算预算

| 项目 | 预算 |
|---|---:|
| Atlas 文件/主数组 | 653,772,840 B（623.486 MiB） |
| V3 float 参数 | 3,987,800 B（3.803 MiB） |
| V4 float 参数 | 11,136 B（10.875 KiB） |
| 输入/输出用户缓冲 | 8 MiB |
| 100 万实测 V3 峰值 RSS | 645.916 MiB |
| 100 万实测 V4 峰值 RSS | 645.948 MiB |

静态主体和实测 RSS 均明显低于 2 GB，约保留 1.35 GiB 安全余量。Atlas CRC32 会在加载后扫描内存一次；SHA-256 只用于离线清单，不进入每请求路径。100 万五次成对运行的查询加 I/O 均值为 V3 0.631870 秒、V4 0.659471 秒；最终模型 5M 长区间的 1 亿线性外推分别为 63.6222 秒和 66.2127 秒，远低于 1800 秒，但仍不是正式 1 亿实测。

## 8. 回退与开关

- `--mode v3`：关闭 V4 残差，同一 V4 二进制复现 V3 逻辑。
- `--mode v4`：默认，仅对 fallback 启用 V4 残差。
- `--mode v4-base`：仅用于逐条验证融合 fallback 与 V3 等价，不作为提交模式。
- `--disable-atlas`：关闭未证明精确的 Atlas，全部进入 V3/V4 模型。
- `--skip-atlas-fingerprint-check`：仅用于诊断；正式运行不建议使用。
- 架构/Atlas 指纹不匹配：默认拒绝启动，不静默复用。
- 构建前校验架构五个 JSON、V3 推理头、残差头和 Atlas 指纹；运行时再次校验 Atlas 头、大小和 CRC32。
- 若后续硬件复测总分不优于 V3，正式配置回退 `--mode v3`。

## 9. 风险与未证明事项

1. 官方尚未明确公开 Golden 训练、离线 Atlas/模型文件和依赖打包规则。
2. 公开固定划分不能代替隐藏架构或隐藏位置分布。
3. Atlas 错误的实际路径原因尚未定位，因此不能通过简单边界 guard 声称修复。
4. 端点 Gap 和 Block 包围盒特征不等于实际路径影响。
5. 最终 C++ 在公开全量上的 `acc_score=95.353385` 混合了 800,304 条新残差训练行和 199,696 条留出行；留出行相对既有 V3 提升 +0.043653。由于既有 V3 曾使用全部公开数据，真正的隐藏集泛化仍未证明。
6. 1 亿时间是 5M 重复输入的线性外推；必须在官方硬件和正式输入上复测，不能称为官方成绩。
7. 当前机器的预计总分为 V3 95.716655、V4 95.730935，差值仅 +0.014280，硬件变化可能改变时间项；因此保留 `--mode v3` 回退。

## 10. 后续实验门槛

在最小 V4 完成 C++ 一致性、准确性和性能验证前，不继续多专家、Atlas 压缩或结构化图算法。Macro、min-plus、Portal、Source/Target Tree、Template Cache 和 Exact Cache 均保持关闭；若以后单独原型，必须同时报告精确一致率、覆盖率、单次节省、额外内存和官方预计总分。
