# V77：半径 1 精确表、P10 容量基座与连接器审计

## 当前结论

本轮完成了两个互相独立的目标：继续缩小不提 Accuracy 的 Atlas 表示开销，以及用新的独立
Dijkstra 路径验证 P10 局部连接器是否可以直接学习成小表。

结论如下：

1. 半径 1 的精确局部表在公开 1M 和独立 608K 上均与 V69 逐行完全一致；半径 1 已是当前验证过的
   最小无损配置。
2. 半径 1 与完整 P10 闭包合计预计为 `51,516,804 B`，100 MB 内仍有 `48,483,196 B` 可用于真正
   提 Accuracy 的局部连接器。
3. P10 核心本身可直接映射，10M 次混合查询为 `0.121099 s`，即 `12.109916 ns/query`；但每条查询
   如果增加多次随机闭包访问，十亿条总时间仍会明显增长。
4. 新生成的 24,576 条完整路径与已有独立 Golden `24,576/24,576` 一致，路径逐段重新计价错误为 0，
   进一步证明 Dijkstra 图与费用模型正确。
5. 直接根据端口、坐标相位和方向去“猜”唯一入口/出口失败。按完整源端点和源区域隔离后，Top-64
   入口/出口联合召回仍很低。因此不能把 Oracle 事件分类器接入 V77；连接器必须按实际局部代价生成，
   不能只记住训练路径标签。
6. V76 的 Hot 路由场复用只节省约 `0.18 s/1M cold run`，并产生输出差异；117 个 Hot 源也没有形成
   可共享的路由组。该实验已拒绝，不进入 V77。

V77 只是新的研究容量基座，P10 尚未参与预测，所以当前 Accuracy 仍是 V69 水平，不能宣称已经达到
99.9%～100%。

## P10 直接嵌入

V74 已证明两方向、1～5 个周期的 10-bit 无损闭包可直接放入 ELF：

| 项目 | 数值 |
|---|---:|
| P10 Up | 23,078,430 B |
| P10 Down | 23,078,430 B |
| P10 合计 | 46,156,860 B |
| V74 ELF（半径 16 + P10） | 86,468,936 B |
| V74 剩余 | 13,531,064 B |
| P10 混合查询 | 12.109916 ns/query |
| V73/V74 独立 608K 输出 | byte-exact |

P10 只解决中间的周期 Block 转移，完整查询仍是：

```text
源端局部连接器 -> 入口 Portal -> P10 精确闭包 -> 出口 Portal -> 目标端局部连接器
```

因此“把 P10 放进二进制”不等于“已经提高 Accuracy”。

## 新 Dijkstra Teacher 与连接器审计

从独立 608K 中按完整源端点分组，确定性选择 24,576 条长距离请求：

| 检查 | 结果 |
|---|---:|
| 独立源 | 96 |
| 完整 Dijkstra 路径 | 24,576 |
| 与原 Golden 不同 | 0 |
| 可严格分解到 P10 | 3,808 |
| 逐段路径计价错误 | 0 |
| 周期 1 / 2 / 3 / 4 | 1,793 / 1,361 / 471 / 183 |
| 唯一入口 / 出口事件 | 785 / 879 |

第一版尝试用单端点特征直接预测 Oracle 事件。完整源端点隔离时：

| Beam | 入口召回 | 出口召回 | 入口和出口同时召回 |
|---:|---:|---:|---:|
| 8 | 1.103% | 1.339% | 0.473% |
| 32 | 7.642% | 6.040% | 2.285% |
| 64 | 12.868% | 15.205% | 6.933% |

源区域隔离结果更低。原因不是 P10 错误，而是全局最优入口由“源局部代价 + 周期核心代价 + 目标局部
代价”共同决定；同一个源端点面对不同目标，本来就可能选择完全不同的入口。只根据源端特征记一个
Top-K 标签，目标函数就是错误的。

这也解释了 P11/P12 的旧结果：全事件组合可在 190 条 Block Teacher 上达到约 99.09%，但独立地缩小
两端候选会快速丢失最优组合。

## 下一步实现原则

下一步不再训练“唯一入口/出口分类器”，而是压缩实际局部代价函数：

1. 把 1,920 个事件分解成 `12 个 Portal x 槽 × 160 个方向状态/落点相位`。
2. 先用联合端点几何的小表选择少量 Portal x 槽；这个小表只控制搜索顺序，不能直接决定答案。
3. 对每个选中的 x 槽，用预计算的端口种子、方向状态与纵向相位转移表生成带精确局部代价的候选。
4. 对候选执行固定次数的 `source_local + P10 + target_local` 查询，并保留 V69 回退值；不运行在线
   Dijkstra/A*，不使用按请求增长的缓存。
5. 如果固定小 Beam 无法证明覆盖，离线蒸馏“条件出口”，而不是增加在线全事件扫描。
6. 每个模块必须同时通过公开 1M、完整源隔离、区域隔离，并报告命中率、Accuracy 增益、随机读取数、
   ELF 字节数和十亿条时间增量。

当前 48.48 MB 预算足以容纳候选 ID 的两级字典，但报告中的 `21.2 MB` 只是 ID 下界，不包含局部代价；
不能据此声称连接器已经装得下。下一门禁必须测量“ID + 代价 + 条件出口”的真实打包大小。

## 当前分数边界

以已经完成的 V72 时间 `118.129753 s`、Consistency=100 计算：

| Accuracy | 总分投影 |
|---:|---:|
| 98.378103%（公开代理） | 97.718068 |
| 99.900000% | 98.935585 |
| 100.000000% | 99.015585 |

所以即便 Accuracy 达到 99.9%，在 118.13 秒下总分仍约为 98.936；总分 99 需要 Accuracy 约
99.98052%。这也是后续门禁必须接近“几乎全精确”的原因。
