# V10 无请求缓存结构替换：实现状态与门禁

## 不可违反的边界

V10 不保存请求、端点对、请求哈希或历史输出，也不根据重复命中改变结果。允许的资产只有由 FPGA
结构推导出的只读表：端口/方向状态、坐标周期相位、局部连接器、路径级 Gap、Block Portal 和周期闭包。
因此唯一请求、重复请求、输入顺序变化时，同一请求的输出严格相同。

## 已实现

1. `generate_nocache_teacher_requests.py` 在生成候选前按完整源端点和 20x100 源区域切分，生成
   24、26、72 邻域及 Block/Gap 专项请求；三套数据无请求、源和区域泄漏。
2. 正向 grouped Dijkstra 与反向同目标 Dijkstra 共用同一精确图，并在 CI 中逐行校验一致性。
3. K48 trace 记录实际分支、标准化位移、路径端点 Gap 与 Block mask，可重新统计各分支失分。
4. P10 上/下方向、1～5 周期闭包由精确图重建，原始矩阵 SHA 门禁后压为 10-bit 直接索引。
   P10 费用来自精确图，所以其中已经包含实际路径的 Gap 和周期 Block 代价。
5. 残差蒸馏不存请求身份，只做一次 fine 数组读取和最多一次 coarse 回退读取；参数选择不读取
   独立区域结果，最终必须在训练、独立源、独立区域三套数据上均为正增益，否则输出空表。
6. `gate_nocache_asset_retirement.py` 默认拒绝删除 K48 的 Short48、Hull 和残差资产。只有固定次数
   局部连接器、P10、三套留出集和无损压缩全部通过后，才授权在新的提交包中退休旧资产。

## 仍需由 Linux CI 产生的证据

- K48 在三套专项唯一请求上的分支误差和准确率；
- 正向/反向 Dijkstra 的逐行一致；
- 固定索引残差表是否三套数据同时正增益；
- P10 两个方向的可复现性、压缩体积与随机访问时间；
- 局部连接器能否在固定小 Beam 下覆盖足够请求。

最后一项是当前真正的算法瓶颈。P10 中段精确并不等于整条路径精确；整条查询必须同时具备
`源局部连接器 → P10 → 目标局部连接器`。在它通过之前删除 Short48/Hull 会造成已知准确率回退。

## 性能阶段顺序

Accuracy 结构门禁通过后才比较 batch 4/8、x86-64-v3/AVX2、线程数和 PGO。所有性能候选先做
逐字节输出一致性，再报告冷启动、解析/预测/格式化/写出、RSS、ELF/资产字节和十亿条投影。
多线程若复制 Atlas、增加内存带宽压力或官方按 CPU 时间计分，应被拒绝，而不是强行合入。
