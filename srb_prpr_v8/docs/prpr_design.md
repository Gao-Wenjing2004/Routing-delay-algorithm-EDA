# PRP-R V8 第一轮设计

## 1. 范围与原则

本轮只实现 `P0_no_atlas` 与纯结构 `P1_primitive_base`，不把公开 Golden 拟合进 P1。目标是先验证“有限周期状态 + 少量可重复原语 + 解析余数”是否具备足够的位移表达能力，再决定是否进入低秩端口和残差学习。

P1 不读取或生成 `local_atlas.bin`，不保存 `(portA, portB, dx, dy)` 延时表，不使用绝对坐标记忆，不做逐请求 Dijkstra/A*，也没有随请求数增长的缓存。

## 2. 周期商图

输入仅为官方 `SRB_Port.json`、`SRB_Arc.json`、`SRB_Net.json`、`SRB_Gap.json` 和 `SRB_Inst.json`。

一个周期状态对应一个作为 Net 终点的 Routing Input，共 160 个。一次状态转移为：

```text
Routing Input
  --Arc(delay)--> Output
  --Net(dx,dy)--> next Routing Input
```

商图不含绝对 SRB 坐标。实测有 2,752 条去重周期转移，160 个状态位于同一个强连通分量。按入边 Net 位移得到 16 个近似状态类；继续加入完整出边签名后得到 160 个精确类，说明 lane 差异真实存在，P1 只把 16 类当作近似压缩而不声称 Exact。

Net 最大跨度从 JSON 自动计算为 12。商图的完整转移、状态类与统计分别保存在 `state_transitions.csv`、`state_equivalence.csv` 和 `quotient_graph_report.md`。

## 3. 原语发现

离线搜索在 16 类商图上进行，路径深度 1～16，单轴位移限制为 ±128。搜索键为 `(current_class, dx, dy)`，保留最低代价路径，并按方向和尺度裁剪 frontier。

只有返回同一近似状态类、且位移非零的路径才能成为可整数重复的周期原语。筛选时使用 16 个方向桶和五个尺度段（≤16、17～32、33～64、65～96、97+），避免只保留单位代价最低的长周期。最终：

- 离线原语 512 条，每个方向桶 32 条；
- 运行时原语 80 条，每个方向桶保留约 12/24/48/80/120 五个尺度；
- 运行时模型还包含 16×16 个状态类连接器；
- 原语总表和运行时模型分别约 37KB 和 0.79MB（JSON）；生成的 C++ 数据头约 0.20MB。

各方向的最低单位代价原语包括：西 `(-120,0)/1500`、东 `(120,0)/1500`、南 `(0,-120)/1250`、北 `(0,120)/1270`；斜向主原语由 `(-120,±24)`、`(120,±24)`、`(±50,±72)`、`(±20,±96)` 等自动形成。

## 4. P1 在线分解

每条请求先从端口结构中选择一个确定性的入口状态和出口状态，再固定评估 7 个候选：

1. 状态类连接器 + 解析余数；
2. 目标方向及相邻两个方向的三个单原语候选；
3. 相邻方向锥两组双原语候选；
4. 水平 + 垂直双原语候选。

双原语计数通过 2×2 整数近似直接求解，只检查 floor/ceil/round/0，复杂度与距离无关。余数按东西南北单位结构下界解析计价。入口、出口和候选数量固定，单请求无堆分配。

公开 100 万位移中，99.9978% 可由双原语加最大 12 的余数表示，允许单原语后覆盖率为 100%。这说明位移基已经形成；但“可表达”不代表当前结构代价能够正确选择该分解。

## 5. 端口、Gap 与 Block 边界

- Source 为查询输入端口时，通过该端口的 Arc 和 Output Net 进入周期图；Source 为 routing Output 时直接沿 Net 进入。
- Target 为 routing Output 时，从周期状态经 Arc 退出。
- 128 个逻辑输出端口没有从周期 Routing Input 发出的退出 Arc；公开请求中这类目标占 34.2158%。P1 对其使用明确标记的解析 fallback，而不伪装成 Exact。
- P1 对直线路径使用官方 Gap 前缀延时；路径相关 Gap 和 Block portal 候选留到 P4，因此当前 Gap 修正不是 Exact 声明。
- P1 不做 Block 绕行。`error_breakdown.csv` 中的 Block 交叠只用于诊断。

## 6. 对照与数据隔离

`P0_no_atlas` 是现有 V3 完全关闭 Atlas 后的输出；`V3` 是现有公开基准输出；P1 的生成只读取架构 JSON。Golden 仅在所有 P1 预测完成后用于评分。

评估同时报告完整公开集与由 `FNV1a(From|To) % 5 == 0` 固定得到的 20% 验证集。由于 P1 未训练，这个留出主要用于验证统计稳定性；后续 P2/P3 必须进一步增加空间、端口和长距离留出，不能把完整公开分数称为泛化分数。

## 7. C++ 工程

C++ 程序流式读取 4MB 块，使用固定数组、端口哈希槽和连续嵌入参数。没有请求全量保存、排序或动态缓存。Linux 静态程序 8.17MB，Windows 本地程序 1.03MB，均远低于 90MB 工程红线。

当前 P1 是研究基线而非推荐提交版本；正式决策见 `analysis/prpr/first_stage_conclusion.md`。
