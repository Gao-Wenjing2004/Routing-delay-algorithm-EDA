# V8 P2：Dijkstra Teacher 蒸馏与固定模板记忆

最后更新：2026-10-02。

## 结论

方案可行，但 Dijkstra 应只放在离线训练侧。正式程序不逐条跑最短路、不携带 Atlas，也不记忆百万条查询；它只携带由 Teacher 蒸馏得到的固定小树，以及端口族、方向、距离段、周期相位/余数、Block/Gap 等可泛化模板。

P1 的纯结构估计只有 68.817773 分，无法靠少量残差直接修好。因此 P2 正式路径改用 V6 的无 Atlas 常数时间回退作为数值基线，同时保留 PRP-R 的 route/state class 作为结构特征。这个调整仍满足“无外部数据、无 Atlas、二进制小于 100 MB”的要求。

## 固定留出消融

训练/验证按 `random_stratified` 规则固定为 800,304 / 199,696 条。下面的验证集未参与 Golden 校准；全量分数包含训练侧，只用于和既有公开百万数据对齐，不能当作隐藏集保证。

当前版本已经跨过公开全量 94.6、120 秒和 100 MB 三条工程线。如果官方一亿条确为公开百万条的随机复制扩充，这个全量结果具有直接参考价值；但固定验证准确度 94.4860 仍低于 94.6，不能据此承诺隐藏新查询也达到 94.6。

### 记忆策略消融

- 完整端口对记忆：公开全量升至 94.625647，但固定验证降至 94.469652，判定为过拟合，拒绝。
- 15 组 Macro10/端口族记忆：公开全量 94.629387，固定验证只到 94.475858；查表多且泛化增益很小，未进入正式 C++。
- 7 组紧凑记忆：float C++ 投影约 126.89 秒；Q20 后准确度几乎不变、速度约 121.99 秒，仍超当时限制，拒绝。
- 3 组紧凑记忆：公开全量 94.603474、固定验证 94.485992；配合端点解析复用后投影 101.591 秒，采用。

## 采用与拒绝的记忆策略

采用的是固定容量的“模板记忆”：

- 端口 family、PRP route/state class；
- 方向、距离段、`dx/dy mod 8/10`；
- source/target 绝对 phase；
- Block mask、Gap 数量与估计代价；
- 8+8 棵浅树的叶子残差，以及三个 Q20 端口族/方向/周期模板。

没有采用：

- `(From, To)` 精确查询缓存；公开百万条几乎没有可利用的精确重复，且不符合泛化要求；
- `(portA, portB, dx, dy)` 稠密答案表；本质上会重新变成 Atlas；
- 在线 A*/Dijkstra；亿条查询的时间不可接受；
- 随查询增长的缓存和绝对坐标 Golden 记忆。

## 下一步

优先研究共享叶子/低秩端口项和按误差桶选择性启用 Student，而不是继续增加树数。目标是在不明显增加平均推理时间的情况下，再提高固定验证约 0.12 分；任何新项都必须继续使用同一固定留出做消融。
