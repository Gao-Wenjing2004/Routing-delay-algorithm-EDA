# PRP-R 第一轮结论

## 结论先行

**P1 纯结构版不能直接作为高分提交：No-Go。** 它满足体积、确定性和速度目标，但准确度只有 68.817773，远低于 94.6 的最低目标。

**PRP-R 研究路线建议有条件继续：Go 到 P2/P3。** 原因是位移表达覆盖已经达到 100%，C++ 性能和体积也留有充足空间；当前误差是高度系统性的端口退出缺失和整体低估，适合用小型低秩端口模型与余数/候选校正解决。若 P2 固定验证仍无法接近 P0，则应停止继续投入 Block/Teacher 阶段。

## 3. 主要误差来源

P1 有 98.7952% 的请求被低估，平均有符号误差为 -204.789，属于系统性缺少固定/端口/候选代价，而不是随机噪声。

第一大问题是 Target 端口：

- 657,842 条可从周期图退出到 routing Output，P1 分数 74.768，MAE 161.4；
- 342,158 条目标为逻辑输出，其中 342,156 条进入结构 fallback，P1 分数 57.378，MAE 290.0；
- 逻辑输出没有 Routing Input → logic Output 的结构 Arc，不能靠增加位移原语解决，必须由端口等价类/低秩端口修正建模。

第二大问题是短距离固定代价：

| Chebyshev 距离 | 请求数 | P1 acc_score |
|---|---:|---:|
| 0–16 | 15,611 | 18.589 |
| 17–48 | 94,407 | 42.039 |
| 49–72 | 100,220 | 56.953 |
| 73–128 | 210,159 | 65.704 |
| 129–256 | 306,892 | 73.796 |
| 257+ | 272,711 | 82.121 |

误差随距离增大而相对下降，说明长距离斜率已经有一定价值，但入口/出口和短余数的固定开销严重缺失。

Block 和 Gap 分组目前与距离高度混杂：交叠两个以上 Block、跨 6 个以上 Gap 的请求反而更准，因为这些请求通常更长。因此不能据此声称 Block/Gap 已解决；P4 仍需做路径相关 Gap 与有限 portal 候选消融。边界组没有显示主要恶化，当前优先级低于端口和短余数。

## 4. 速度、体积与一致性

- Windows C++ 百万条五次外部计时均值：1.00243 秒，约 997,578 QPS。
- 线性外推 1 亿条：100.24 秒；这是本机外推，不是官方平台实测。
- 五次百万条输出 SHA-256 完全相同：`861ca94568c79ee0b0447586bb1415b7710e54214365e4e68ea731dc2854364a`。
- Windows 性能二进制：1,033,216 bytes。
- Linux x86-64 musl 静态二进制：8,165,056 bytes。
- 嵌入模型头：197,497 bytes；外部 Atlas：0 bytes。
- Python 与 C++ 前 10,000 条预测逐条一致，mismatch=0。

按 P1 准确度、100.24 秒外推时间和一致性 100 粗算，总分约 74.22；准确度不达标，所以不能因体积和速度合格而提交。

## 5. 下一阶段闸门

建议只继续以下最小路径：

1. P2：4/8/16 维低秩 Source/Target 端口模型，优先覆盖逻辑输出；总参数先限制在 5 万以内。
2. P3：针对短距离、入口/出口固定开销和候选选择训练小型余数模型。
3. 固定 FNV 留出之外，再做 Source/Target 区域、端口族、长距离与 Block 分层留出。
4. P2 固定验证必须显著高于 P1，并以逼近或超过 P0=94.05 为阶段目标；否则 No-Go，不进入复杂 Block/Teacher。

当前不建议增加原语数量：位移覆盖已经饱和，继续堆原语不能解决 34.2% 目标端口退出缺失和 98.8% 系统性低估。
