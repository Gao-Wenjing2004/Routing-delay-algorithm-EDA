# V7 提交包

上传本目录的 **submission.zip**。ZIP 只含 `bin/estimate`，Linux 权限 0755。

```sh
./bin/estimate -in request.csv -out estimate_result.csv
```

程序为单线程 Linux x86-64 ELF，在用户提供的官方镜像中编译。端口距离表与模型已嵌入程序，不需要额外配置、模型文件、Golden CSV 或网络访问。输出表头为 `From,To,Delay`，保持请求顺序，Delay 为整数。

## 本轮结果

- 同一 20 万留出集准确率得分：V6 **94.871842 → V7 95.647606**。
- 同一留出集完全精确比例：**10.2450% → 15.3055%**。准确率得分不是逐条完全正确比例。
- 7 轮同核单线程测试，百万条流式 CPU 均值：**0.441574 → 0.359596 秒**，减少约 18.6%；百万条完整进程 CPU 均值为 **0.737701 → 0.682779 秒**。
- 10 亿条 CPU 外推约 **359.919 秒**；测量范围 303.084–477.577 秒。用户提供的对手平台 CPU 为 359.618 秒，两者环境未核对，不能视为已追平。
- 按 80% 准确率、15% 时间、5% 一致性，1800 秒时间上限计算，当前估算总分约 **93.52**。没有隐藏平台成绩，尚未达到 100 分准确率或 97 分总分。
- 正式模型在允许的公开 100 万训练数据上的回归得分为 95.979644；这不是留出集成绩。

仅重复运行现有百万条输入，没有执行十亿条压力测试。CPU 外推公式为 `百万条完整进程 CPU + 999 × 百万条流式 CPU`，一次性初始化与退出均计入。源码选择过程、论文和开源原型实测保存在 `../srb_fast_v7/`，主要说明见该目录 `research/论文与实现取舍.md`。

此前 V6 文档的约 289 秒来自 Windows 墙钟外推，本轮约 442 秒的 V6 基准来自 Linux 同核 CPU 计时，不能跨环境直接比较。上述 V6→V7 改善使用本轮同环境成对测量。离线准备若另按 300 秒预算计入，V7 完整流程情景为约 660 秒、91.02 分；这 300 秒是假设，不是完整准备阶段实测，上述 93.52 只用于提交文件运行阶段。

## 验证与文件

- 已在 2,000,000,000 字节地址空间限制下运行；百万条检查中子进程峰值 RSS 1,282,920,448 字节（约 1.28 GB）。
- 五次百万条输出 MD5 相同；嵌入资产前后的输出逐字节相同。
- 检查了 BOM、CRLF、无末尾换行、空输入、跨缓冲区边界、异目录/符号链接运行、错误退出、输出写入失败。
- `qa/validation_report.json`：运行检查；`qa/optimization_report.json`：精度与 CPU 原始记录；`qa/package_report.json`：ZIP 权限、CRC 与 SHA256；`qa/local_receipt.json`：下载校验和源码指纹；`qa/clean_container_report.json`：只挂载解压程序的干净容器运行检查。
- `src/` 是正式编译源码快照；`bin/estimate` 是已编译的 Linux 文件，不能作为 Windows EXE 直接运行。

重建可使用 `rebuild_with_docker.ps1 -LoadImage`；它需要 Docker、原始镜像和 `../srb_fast_v7/endpoint_packed.bin`。当前提供的 ZIP 已完成编译，上传无需重建。原 V6 包仍保留在 `../submission_v6_20260919/`。

V7 的全图预测仍包含近似模型，边界、gap/block 与未覆盖端口组合不能保证精确最短路，既有不可达诊断请求也尚未支持。完整无损解码检查只证明距离表压缩没有改变存储值。
